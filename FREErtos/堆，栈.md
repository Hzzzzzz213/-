# 1. `void *my_malloc(...)` 为什么看起来是 void 却有返回值？

> 重点拆分：`void *` 是一个**整体类型：void 指针（通用指针）**，不是 `void`（无返回值）！

- `void my_func()`：返回值写单独 `void` → **没有返回值，不能 return 任何数据**
- `void *my_func()`：返回值类型是 `void*` → **返回一个内存地址（指针）**

**任务栈 uxStackDepth**

- 每个任务独立私有栈，用来保存局部变量、函数调用、**上下文**。
- 单位：**word（字）**，STM32 32 位单片机，1word = 4Byte。
- 例：uxStackDepth=100 → 100 字 = 400 字节。
- 栈太小 → 栈溢出，程序死机跑飞；栈太大，浪费 RAM。
- `configMINIMAL_STACK_SIZE`：空闲任务最小栈深度。
- `uxTaskGetStackHighWaterMark()`：栈高水位标记，查看运行时剩余最小栈空间，用来评估栈大小是否够用。
## 任务上下文切换（核心）

> 上下文 = 任务运行时 CPU 全部寄存器的值（R0~R15、xPSR 等）

1. 切换时机：SysTick 定时器中断触发（时间片轮转），或者高优先级任务就绪。
2. 切换过程： ① **保存现场**：暂停当前正在运行任务，把 CPU 寄存器全部存入**当前任务自己的任务栈**。 ② 在就绪链表，选出最高优先级就绪任务。 ③ **恢复现场**：把选中任务栈里保存的寄存器，重新放回 CPU 寄存器。 ④ CPU 继续运行这个新任务。
3. 一句话理解： 每个任务暂停时，把寄存器打包存到自己栈；轮到它运行，再从栈把寄存器放回 CPU，仿佛任务从没中断。
