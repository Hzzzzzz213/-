

多个队列/信号量，统一交给一个任务监听。 队列集里面存放的不是业务数据，而是**队列句柄**。

> 场景例子：红外遥控器队列、旋转编码器队列，都加入同一个队列集，InputTask只需要阻塞读取队列集，就能知道哪个队列来了数据。

✅ 驱动和业务分离：驱动只负责往队列放原始数据，不做业务解析；业务任务统一解析。

## 使用步骤

1. 创建普通队列A、队列B
2. 创建队列集S，队列集长度 = 所有成员队列最大可存放事件总数
3. 将A、B加入队列集
4. 往A写数据 → 自动把A的句柄放进队列集
5. 往B写数据 → 自动把B的句柄放进队列集
6. 任务调用`xQueueSelectFromSet`读取队列集，拿到句柄，再去读对应队列的数据

## API

### 1. 创建队列集

```c
QueueSetHandle_t xQueueCreateSet( const UBaseType_t uxEventQueueLength );
```

- uxEventQueueLength：队列集最多存多少个句柄
- 返回：队列集句柄；NULL代表内存不足失败

### 2. 将队列（信号量）加入队列集

```c
BaseType_t xQueueAddToSet( QueueSetMemberHandle_t xQueueOrSemaphore,
                            QueueSetHandle_t xQueueSet );
```

- xQueueOrSemaphore：要加入的队列/信号量句柄
- xQueueSet：队列集句柄
- 返回：pdTRUE成功，pdFALSE失败
==xQueueAddToSet 只能把空队列加入队列集；6050 任务先往队列写了数据，队列不再是空，这个队列就没法加到队列集里了。==

### 3. 读取队列集（阻塞等待）

```
QueueSetMemberHandle_t xQueueSelectFromSet( QueueSetHandle_t xQueueSet,
                                            TickType_t const xTicksToWait );
```

- xQueueSet：队列集句柄
- xTicksToWait：阻塞等待时间（tick）
    - 0：没有数据立刻返回
    - portMAX_DELAY：一直阻塞，直到有事件
- 返回：拿到有数据的队列句柄；NULL失败

## 注意：

1. `xQueueAddToSet`：**只是登记绑定关系**，告诉内核：这个队列是属于这个队列集的。此时队列集里**不会自动写入句柄**。
2. 当往这个队列**成功写入数据**（入队成功）时，内核自动把这个队列的句柄放入队列集。
3. 如果队列本身已经满了 → `xQueueSend`入队失败 → 不会往队列集里放句柄。

额外补充两个容易踩坑点：

- 队列集本身也有长度上限，如果队列集满了，就算成员队列入队成功，**句柄也写不进队列集**，事件丢失。
- 一个队列只能绑定到一个队列集，不能同时加到多个队列集。


## 补充考点

- 队列集存的是句柄，不是传感器、按键这类业务数据
- 适合：一个任务要等待多个不同来源事件
- 局限：只能知道“哪个队列有数据”，不会直接拿到数据
