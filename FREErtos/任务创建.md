

## 一、什么是任务

在 FreeRTOS 中，**任务就是一个函数**，原型如下：

```c
void ATaskFunction(void *pvParameters);
```

### 任务函数特点

1. **不能返回**
   - 通常写成无限循环 `for(;;)`。
   - 如果任务函数要退出，必须调用：
     ```c
     vTaskDelete(NULL);  // 删除自己
     ```

2. **同一个函数可以创建多个任务**
   - 多个任务可以运行同一个任务函数。
   - 区别主要来自：
     - 每个任务有自己的栈；
     - 创建任务时可以传入不同参数。

3. **局部变量与全局变量**
   - 局部变量：每个任务有自己的副本，放在各自任务栈中。
   - 全局变量、静态变量：所有任务共享同一个副本，需要防止冲突。

示例：

```c
void ATaskFunction(void *pvParameters)
{
    int32_t lVariableExample = 0;  // 不同任务有各自副本

    for(;;)
    {
        /* 任务代码 */
    }

    vTaskDelete(NULL);  // 退出循环时删除自己
}
```

## 二、创建任务

FreeRTOS 提供两种创建方式：

1. **动态分配内存**：`xTaskCreate`
2. **静态分配内存**：`xTaskCreateStatic`

---

## 三、动态创建任务：xTaskCreate

函数原型：

```c
BaseType_t xTaskCreate(
    TaskFunction_t pxTaskCode,              // 任务函数
    const char *const pcName,               // 任务名字
    const configSTACK_DEPTH_TYPE usStackDepth, // 栈大小，单位 word
    void *const pvParameters,               // 传给任务函数的参数
    UBaseType_t uxPriority,                 // 优先级
    TaskHandle_t *const pxCreatedTask       // 任务句柄
);
```

### 参数说明

| 参数              | 说明                                                               |
| --------------- | ---------------------------------------------------------------- |
| `pxTaskCode`    | 任务函数指针。任务通常不退出；退出时调用 `vTaskDelete(NULL)`                         |
| `pcName`        | 任务名字，FreeRTOS 内部不使用，主要用于调试；长度受 `configMAX_TASK_NAME_LEN` 限制      |
| `usStackDepth`  | 任务栈大小，单位是 **word**。例如传入 100，表示 100 word，即 400 字节                 |
| `pvParameters`  | ==调用任务函数时传入的参数，即 `pxTaskCode(pvParameters)`==                    |
| `uxPriority`    | 优先级范围：`0 ~ configMAX_PRIORITIES - 1`。数值越小优先级越低；传入过大值会被调整为最大合法优先级 |
| `pxCreatedTask` | 用于保存创建出来的任务句柄。以后操作该任务时需要；不想使用可传 `NULL`                           |

### 返回值

- 成功：`pdPASS`
- 失败：`errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY`
  - 失败原因只有内存不足。
  - 注意：文档中常说失败返回 `pdFAIL`，这是不对的。
  - `pdFAIL` 是 0，`errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY` 是 -1。

## 四、静态创建任务：xTaskCreateStatic

函数原型：

```c
TaskHandle_t xTaskCreateStatic(
    TaskFunction_t pxTaskCode,          // 任务函数
    const char *const pcName,           // 任务名字
    const uint32_t ulStackDepth,        // 栈大小，单位 word
    void *const pvParameters,           // 任务参数
    UBaseType_t uxPriority,             // 优先级
    StackType_t *const puxStackBuffer,  // 静态分配的栈 buffer
    StaticTask_t *const pxTaskBuffer    // 静态分配的任务结构体
);
```

### 与动态创建的主要区别

| 项目 | 动态创建 `xTaskCreate` | 静态创建 `xTaskCreateStatic` |
|---|---|---|
| 栈内存 | FreeRTOS 动态分配 | 用户提供 `puxStackBuffer` |
| 任务结构体 | FreeRTOS 动态分配 | 用户提供 `pxTaskBuffer` |
| 返回值 | 成功 `pdPASS`，失败内存不足错误码 | 成功返回任务句柄，失败返回 `NULL` |
| 最后两个参数 | `pxCreatedTask` | `puxStackBuffer`、`pxTaskBuffer` |

静态栈 buffer 大小应为：

```c
usStackDepth * 4
```

因为一个 word 通常为 4 字节。

## 六、示例2：使用任务参数

示例代码：`06_create_task_use_params`

==多个任务可以使用同一个函数，通过**不同参数**体现差异。==

**我们说过，多个任务可以使用同一个函数，怎么体现它们的差别？ 
1.栈不同 
2.创建任务时可以传入不同的参数**

定义结构体：

```c
 * 定义一个用于LCD显示信息的结构体。
 * 作用：在创建任务时，可以通过 pvParameters 把这个结构体传给任务函数，
 * 使得同一个任务函数可以根据传入的不同结构体，在不同的位置显示不同的内容。
 */
struct DisplayInfo {
    int x;              // 字符在LCD屏幕上显示的 X 坐标（横坐标）
    int y;              // 字符在LCD屏幕上显示的 Y 坐标（纵坐标）
    const char *str;    // 要显示的字符串指针（例如："task1"）
};
```

任务函数：

```c
/* 
 * 标准的 FreeRTOS 任务函数。
 * 参数：pvParameters 是创建任务时（xTaskCreate 的第4个参数）传入的 void* 类型指针。
 */
void vTaskFunction(void *pvParameters)
{
    /* 
     * 将 void* 类型的参数强制转换为 struct DisplayInfo* 类型。
     * 因为 FreeRTOS 底层只认 void* 指针，我们需要明确告诉编译器这块内存是什么结构。
     * 注意：这里的 info 是局部变量，存放在当前任务的私有栈中。
     */
    struct DisplayInfo *info = pvParameters;
    
    /* 定义一个无符号32位整型变量作为计数器，初始化为 0 */
    uint32_t cnt = 0;
    
    /* 定义一个无符号32位整型变量，用于接收 LCD_PrintString 的返回值（字符串长度） */
    uint32_t len;

    /* FreeRTOS 的任务函数主体通常是一个无限循环（死循环） */
    for(;;)
    {
        /* 
         * 1. 在 LCD 指定坐标 (info->x, info->y) 处打印传入的字符串 (info->str)。
         * 2. 返回值 len 为打印的字符串长度。 
         */
        len = LCD_PrintString(info->x, info->y, info->str);
        
        /* 
         * 1. 紧跟在字符串后面打印递增的数字 (cnt)。
         * 2. len + 1 表示打印的 X 坐标偏移量（字符串长度+1个空格的偏移）。
         * 3. 注意 cnt++：这里先使用当前的 cnt 值进行打印，打印完后 cnt 自增 1。
         */
        LCD_PrintSignedVal(len + 1, info->y, cnt++);
        
        /* 
         * 调用毫秒级延时函数，延时 500 毫秒。
         * 在 FreeRTOS 中，延时函数会让当前任务进入阻塞态，主动交出 CPU 控制权，
         * 让其他就绪的任务去运行。同时也实现了“每500ms刷新一次数字”的视觉效果。
         */
        mdelay(500);
    }
    
    /* 
     * 注意：因为是 for(;;) 无限循环，程序永远不会执行到这里。
     * 根据 FreeRTOS 规范，如果任务函数打算退出，必须在退出前调用 vTaskDelete(NULL)。
     */
}
```

创建任务时传入不同参数：

```c
xTaskCreate(LcdPrintTask, "task1", 128, &g_Task1Info, osPriorityNormal, NULL);
xTaskCreate(LcdPrintTask, "task2", 128, &g_Task2Info, osPriorityNormal, NULL);
xTaskCreate(LcdPrintTask, "task3", 128, &g_Task3Info, osPriorityNormal, NULL);
```

要点：

- 同一个任务函数 `LcdPrintTask` 创建了 3 个任务；
- 每个任务栈不同；
- 每个任务收到的 `pvParameters` 不同；
- 因此显示内容不同。

## 七、删除任务

函数原型：

```c
void vTaskDelete(TaskHandle_t xTaskToDelete);
```

参数：

| 参数 | 说明 |
|---|---|
| `xTaskToDelete` | 要删除的任务句柄；传入 `NULL` 表示删除自己 |

三种删除方式：

1. **删除自己**
   ```c
   vTaskDelete(NULL);
   ```

2. **被别的任务删除**
   - 别的任务执行 `vTaskDelete(自己的句柄)`。

3. **删除别的任务**
   - 执行 `vTaskDelete(别的任务句柄)`。

## 八、示例3：删除任务

示例代码：`07_delete_task`

功能：

- 监测红外遥控器；
- 按下 `play` 键：创建播放音乐任务；
- 按下 `power` 键：删除音乐播放任务，并停止蜂鸣器。

核心逻辑：

```c
while (1)
{
    if (0 == IRReceiver_Read(&dev, &data))
    {
        if (data == 0xa8)  /* play */
        {
            extern void PlayMusic(void *params);

            if (xSoundTaskHandle == NULL)
            {
                LCD_ClearLine(0, 0);
                LCD_PrintString(0, 0, "Create Task");

                ret = xTaskCreate(
                    PlayMusic,
                    "SoundTask",
                    128,
                    NULL,
                    osPriorityNormal,
                    &xSoundTaskHandle
                );
            }
        }
        else if (data == 0xa2)  /* power */
        {
            if (xSoundTaskHandle != NULL)
            {
                LCD_ClearLine(0, 0);
                LCD_PrintString(0, 0, "Delete Task");

                vTaskDelete(xSoundTaskHandle);
                PassiveBuzzer_Control(0);  // 停止蜂鸣器
                xSoundTaskHandle = NULL;
            }
        }
    }
}
```

要点：

- 创建音乐任务前检查 `xSoundTaskHandle == NULL`，防止重复创建；
- 删除任务后要停止蜂鸣器；
- 删除后把句柄置为 `NULL`，便于下次重新创建。

## 九、重点记忆

1. 任务函数原型：
   ```c
   void TaskFunction(void *pvParameters);
   ```

2. 任务函数不能返回，通常无限循环；退出必须：
   ```c
   vTaskDelete(NULL);
   ```

3. 创建任务：
   - 动态：`xTaskCreate`
   - 静态：`xTaskCreateStatic`

4. 栈大小单位是 **word**，通常 1 word = 4 字节。

5. 同一任务函数可创建多个任务：
   - 栈不同；
   - 参数不同；
   - 局部变量各自独立；
   - 全局/静态变量共享，要防冲突。

6. 删除任务：
   ```c
   vTaskDelete(handle);  // 删除指定任务
   vTaskDelete(NULL);    // 删除自己
   ```

7. 动态创建失败返回值注意：
   - 成功：`pdPASS`
   - 失败：`errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY`
   - 不是 `pdFAIL`

---

## 十、一句话总结

FreeRTOS 任务本质是一个**不返回的 C 函数**；可用 `xTaskCreate` 或 `xTaskCreateStatic` 创建，通过句柄和参数管理不同任务；任务退出或被删除时使用 `vTaskDelete`，删除自己传 `NULL`。
