
## 一、 信号量的核心概念

### 1. 什么是信号量？
信号量主要用于任务间、任务与中断间的**状态传递**和**资源管理**（队列主要用于传输数据）。
*   **信号（通知）**：通知某个事件发生了。
*   **量（数量）**：表示资源的数量（比如：包子数量、空停车位数量）。
*   **核心操作**：
    *   **Give（给出）**：计数值 +1，唤醒等待的任务。
    *   **Take（获取）**：计数值 -1，如果没有资源则可能阻塞。

### 2. 典型应用场景
*   **计数型（事件计数）**：中断产生时 `Give`（+1），任务处理时 `Take`（-1）。
*   **资源管理（同步）**：访问共享资源前 `Take`（-1），用完释放资源后 `Give`（+1）。
*   **生产者-消费者**：生产者 `Give`，消费者 `Take`。

---

## 二、 信号量 vs 队列（重点区别）

| 对比项 | 队列 (Queue) | 信号量 (Semaphore) |
| :--- | :--- | :--- |
| **数据存储** | 可容纳多个数据，分配数据空间 | **只维护一个计数值**，不存数据，更省内存 |
| **生产者满状态** | 没有空间时**阻塞** | 计数值达最大值时，直接返回失败（**不阻塞**） |
| **消费者空状态** | 没有数据时**阻塞** | 计数值为0（无资源）时，**阻塞**等待 |

---

## 三、 信号量的分类

1.  **二进制信号量 (Binary Semaphores)**
    *   **计数值范围**：只能是 **0 或 1**。
    *   **初始值**：创建时默认初始值为 **0**（需要用 `Give` 置为 1 后才能 `Take`）。
    *   **用途**：常用于**任务同步**（如：中断通知任务）。
2.  **计数型信号量 (Counting Semaphores)**
    *   **计数值范围**：0 ~ 设定的最大值。
    *   **初始值**：创建时可以设定初始值。

## 四、 常用 API 函数

### 1. 创建与删除
*   **创建二进制信号量**：
    ```c
    SemaphoreHandle_t xSemaphoreCreateBinary(void);
    ```
    *(注：创建后初始值为0，通常需要主动调用一次 `Give`)*
*   **创建计数型信号量**：
    ```c
    SemaphoreHandle_t xSemaphoreCreateCounting(UBaseType_t uxMaxCount, UBaseType_t uxInitialCount);
    // uxMaxCount: 最大计数值；uxInitialCount: 初始计数值
    ```
*   **删除信号量**：
    ```c
    void vSemaphoreDelete(SemaphoreHandle_t xSemaphore);
    ```
*(注：以 `Static` 结尾的是静态创建方法，不占用动态内存)*

### 2. Give / Take 操作
分为 **任务中** 和 **中断中** 两个版本：

| 操作 | 任务中使用 | 中断 (ISR) 中使用 |
| :--- | :--- | :--- |
| **Give (+1)** | `xSemaphoreGive()` | `xSemaphoreGiveFromISR()` |
| **Take (-1)** | `xSemaphoreTake()` | `xSemaphoreTakeFromISR()` |

#### 🔴 xSemaphoreTake (获取信号量)
```c
BaseType_t xSemaphoreTake(SemaphoreHandle_t xSemaphore, TickType_t xTicksToWait);
```
*   `xTicksToWait` (阻塞时间)：
    *   `0`：不阻塞，拿不到马上返回。
    *   `portMAX_DELAY`：死等，直到拿到为止。
    *   其他值：阻塞指定 Tick 数（可用 `pdMS_TO_TICKS(100)` 宏转换为毫秒）。

#### 🔴 xSemaphoreGiveFromISR (中断中给出信号量)
```c
BaseType_t xSemaphoreGiveFromISR(SemaphoreHandle_t xSemaphore, BaseType_t *pxHigherPriorityTaskWoken);
```
*   `pxHigherPriorityTaskWoken`：如果给出信号量唤醒了一个**更高优先级**的任务，该指针会被置为 `pdTRUE`。在中断退出前，系统需根据此值决定是否进行任务切换。

## 五、 实战示例分析（通行证小车游戏）

### 场景1：使用计数型信号量（3辆车，2张通行证）
*   **创建**：`g_xSemTicks = xSemaphoreCreateCounting(3, 2);` （最大3，初始2）。
*   **逻辑**：
    1.  小车任务启动，先 `xSemaphoreTake`。前两辆车拿到通行证，第三辆车进入阻塞。
    2.  小车向右行驶，到达终点后，调用 `xSemaphoreGive` 归还通行证并删除自己。
    3.  第三辆车被唤醒，拿到通行证，开始行驶。
*   **现象**：car1、car2 同时行驶，谁先到终点，car3 才开始行驶。

### 场景2：使用二进制信号量（3辆车，1张通行证）
*   **创建与初始化**：
    ```c
    g_xSemTicks = xSemaphoreCreateBinary(); // 初始值为 0
    xSemaphoreGive(g_xSemTicks); // 手动 Give 一次，使其变为 1
    ```
*   **现象**：car1 先开，到终点后 car2 开，最后 car3 开。（依次串行执行）。

## 六、 核心记忆点总结

1.  **本质**：信号量就是一个**带有阻塞机制的计数器**。
2.  **二值 vs 计数**：二值只能 0/1（初始为0需手动给），计数可自定义最大值和初始值。
3.  **超时机制**：Take 不到时，可以在 `xTicksToWait` 参数中设置死等 (`portMAX_DELAY`) 或超时放弃。
4.  **ISR 注意**：中断里只能用带 `FromISR` 后缀的函数，且必须传入 `pxHigherPriorityTaskWoken` 变量。
