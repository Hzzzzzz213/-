
# reeRTOS 同步与互斥 笔记（百问网）

## 1. 错误方案 1：简单标志位判断

```c
static int bCanUse = 1;
if(bCanUse)
{
    bCanUse = 0;
    //操作LCD
    bCanUse = 1;
}
```

❌ 问题：**判断 和 赋值 是两句 C 代码，不是原子操作** 场景：任务 A 读到`bCanUse=1`，还没执行`bCanUse=0`，就被任务切换打断；任务 B 同样读到`bCanUse=1`。 结果：A、B 两个任务同时进入临界区，互斥失效。

> 原子操作：整个过程**不能被打断**，一口气执行完。

## 2. 错误方案 2：先自减再判断

```c
bCanUse--;
if(bCanUse == 0)
{
    //操作LCD
    bCanUse++;
}
else
{
    bCanUse++;
}
```

❌ 问题：`bCanUse--`底层拆成 3 条汇编，依然可被打断 汇编拆分：

1. LDR 读取变量到寄存器
2. DEC 寄存器里的值 - 1
3. STR 写回内存

场景：A 读取值 = 1，还没写回就被切走；B 进来读取 = 1、减到 0、写回，拿到 LCD 使用权；切回 A，A 寄存器里还是 1，减 1 后写回 0，A 也拿到使用权。 结果：两个任务同时访问 LCD，互斥失效。

✅ 核心原因：读 - 改 - 写三步，不是原子的，可以被任务抢占打断。

## 3. 改进思路：关闭中断（关中断实现原子）

原理：**关闭中断 → 调度器依赖 SysTick 中断，中断关了，任务切换就不会发生**，这段代码不会被别的任务打断。

> 注意：关中断只适合很短的临界区，不能长时间关！

### 示例 1 改进版（关中断保护判断 + 抢占标记）

```c
static int bCanUse = 1;
disable_irq();       //关中断，禁止任务切换
if(bCanUse)
{
    bCanUse = 0;
    enable_irq();    //开中断
    //访问LCD（这里是耗时操作，不需要关中断）
    bCanUse = 1;
    return 0;
}
enable_irq();
return -1;
```

关键点：**只把【判断 + 抢占标记】放在关中断里面；LCD 耗时操作放在开中断之后**，避免长时间关中断影响系统节拍。

### 示例 2 改进版（自减操作关中断保护）

```c
static int bCanUse = 1;
disable_irq();
bCanUse--;           //读改写全程关中断，变成原子
enable_irq();

if(bCanUse == 0)
{
    //访问LCD
    bCanUse++;
    return 0;
}
else
{
    disable_irq();
    bCanUse++;
    enable_irq();
    return -1;
}
```

## 4. 考点总结

1. 裸机里简单标志位好像能用，RTOS 多任务下**判断 + 赋值不是原子操作，互斥失效**。
2. `变量--`底层是【读→改→写】三步汇编，天然非原子，依然会被任务切换打断。
3. 关中断可以让一段代码原子执行，阻止任务切换；**临界区一定要短**。
4. FreeRTOS 工程标准方案：**互斥信号量（xSemaphoreCreateMutex）**，而不是自己写标志 + 关中断。
    - 自己标志 + 关中断：简单、适合极简场景；缺点：容易长时间关中断，优先级翻转问题处理麻烦
    - 互斥量：RTOS 原生，支持优先级继承，推荐用来保护 LCD、串口这类共享资源
