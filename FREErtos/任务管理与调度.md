## 一、任务 4 大核心状态

1. **Ready（就绪态）**：任务已经满足运行条件，等待 CPU，还没开始执行；放在**就绪列表 ReadyList**
2. **Running（运行态）**：任务正在占用 CPU 执行；单核 MCU 同一时刻**只能有 1 个任务处于 Running**
3. **Blocked（阻塞态）**：任务等待事件（延时 vTaskDelay、信号量、队列等），暂时不能运行；放入**阻塞列表 DelayedTaskList**，等待事件到期后回到就绪态
4. **Suspended（挂起态）**：调用 vTaskSuspend 挂起任务，除非主动恢复，否则永远不参与调度，不放在就绪 / 阻塞列表

> 状态流转：就绪 → 运行；运行 → 就绪 / 阻塞 / 挂起；阻塞事件完成 → 就绪；挂起恢复 → 就绪

## 二、FreeRTOS 调度规则（核心：**固定优先级抢占式 + 同优先级时间片轮转**）

1. **高优先级优先（抢占式）**
    - 只要就绪队列里出现更高优先级任务，**立刻抢占**当前正在运行的低优先级任务，低优先级任务被切回就绪态
    - 低优先级任务运行时，高优先级任务一旦就绪，低优先级任务就无法继续执行
    - 一旦高优先级任务阻塞 / 挂起，低优先级任务马上恢复运行
2. **同优先级任务：时间片轮流执行**
    - 多个相同最高优先级就绪任务，轮流占用 CPU，每个任务占用一个 Tick 时间片
    - 时间片耗尽，切换到同优先级下一个就绪任务

## 三、内核列表管理机制

1. **就绪列表 ReadyList**：数组形式，数组下标对应任务优先级；每个下标挂载对应优先级的任务链表。调度器在这里查找**最高优先级就绪任务**
2. **阻塞列表 DelayedTaskList**：存放延时 / 等待事件的阻塞任务；内核在 SysTick 中断（Tick 中断）里扫描阻塞列表：
    - Tick++
    - 判断阻塞任务延时是否到期
    - 到期任务移到就绪列表，触发一次任务调度

## 四、任务调度触发时机

1. SysTick 定时器中断（时间片到点，检查阻塞任务）
2. API 函数调用：vTaskDelay、xSemaphoreTake 等，任务主动进入阻塞，触发调度
3. 中断里释放信号量 / 队列，让高优先级任务变为就绪，触发抢占

## 五、FreeRTOS 调度器的作用

1. **任务选择** 从就绪列表中，选出**优先级最高**的就绪任务；同优先级就按时间片轮流选。决定 “下一个该跑谁”。
2. **抢占与轮转管理**
    - 当更高优先级任务就绪，立刻抢占当前任务，保证紧急任务优先执行；
    - 同优先级多个就绪任务，用时间片轮转，让多个任务轮流使用 CPU。
3. **上下文切换** 任务切换时，**保存当前任务寄存器、堆栈现场**，再加载新任务的现场，实现任务 “暂停 - 恢复”，让每个任务仿佛独占 CPU 运行。
4. ==**配合事件管理**== 配合阻塞列表：延时、等待信号量 / 队列的任务进入阻塞，不再占用 CPU；等待事件到期后，把任务放回就绪列表，再交由调度器安排运行。
5. **响应外部事件（中断）** 中断释放信号量等操作让高优先级任务就绪时，调度器可以触发抢占，快速响应紧急事件。
