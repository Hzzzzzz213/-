# 立即数「嵌入 CPU 指令」 vs RAM 内存

## 1、RAM（内存盒子）

RAM 就是单片机的**运行内存，一个个存储盒子**。

变量就放在 RAM 盒子里面。

```
int a = 100;
```

- `a`：变量，**存放在 RAM**，有盒子、有地址，可以`&a`取地址，可以修改`a=200`。
- `100`：**立即数**

> CPU 要把 100 这个数字，复制到 RAM 的 a 盒子里面。

### ✨嵌入 CPU 指令：

**立即数`100`，这个数字本身，直接写在机器指令代码里面，放在 Flash，不占 RAM 盒子。**


```
MOV  R0, #100    ; #100 就是立即数！数字100直接编码在这条指令内部
STR  R0, [SP]    ; 把R0里面的值100，存入RAM内存的变量a
```

- `MOV R0,#100`：这一条指令，存在 Flash（程序闪存）。
- `#100`这个数字，**打包嵌在 MOV 这条指令本身里面**。
    
    👉 100 没有占用任何 RAM 盒子，它就在指令代码里面。


## 形象比喻

- **RAM：一排抽屉（盒子）**，可以存数据，可以改，断电数据消失。变量放在抽屉。
- **Flash：一本书（存你的程序代码）**，所有 CPU 指令写在这本书书页上。

> 立即数 = 直接写在书本某一行指令旁边的数字。
> 
> 它写在书上（Flash 指令内部，嵌入指令），**没有放进抽屉 (RAM)**。
> 
> 它不属于抽屉里的数据，只是书本文字的一部分。



```
int a = 100;
```

1. 书本 (Flash) 有一行指令：把数字【100】拿出来
2. CPU 读到这条指令，从指令里面读出 100
3. 把 100 放到抽屉 a（RAM）里面

👉 `100` 在书上（嵌入指令）；`a` 在抽屉 RAM。

## 回到你 STM32 的例子

c

运行

```
#define TIM2_BASE 0x40000000U
```

`0x40000000U` 立即数。

编译之后，这个数字**直接嵌进 CPU 指令里面，放在 Flash，不占用 RAM，没有抽屉盒子**。

所以不能写 `&0x40000000`

> `&`是找抽屉 (RAM) 的门牌号，这个数字根本没有放进抽屉，写在指令书上，当然拿不出门牌号。

### 区分三件东西

1. **RAM（抽屉）**：局部变量、全局变量。有地址，可以 &。断电丢失。
2. **Flash（书本）**：CPU 指令代码、常量字符串。程序烧录在这里。
3. **立即数**：写死数字，**嵌入在 Flash 的 CPU 指令内部**，不在 RAM 抽屉，没有地址，不能 &。

```
TIM_TimeBaseInit(TIM2, &tim_conf);
```

1. ==`tim_conf`：局部结构体变量 → **存 RAM 抽屉**，有地址，用`&tim_conf`拿到抽屉编号。==
2. ==`TIM2`宏展开得到`((TIM_TypeDef *)0x40000000U)`==
    
    ==`0x40000000`是立即数，**嵌入 CPU 指令，不在 RAM，没有抽屉，禁止 &**。==
