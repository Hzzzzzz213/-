# 一、错误示范：#include .c 引发重复定义

工程两个文件：

`led.c`（LED 驱动函数）、`main.c`（主函数）

## 1. led.c

c

运行

```
#include <reg51.h>

void led_on(void)
{
    P0 = 0x00;
}
```

## 2. main.c 错误写法（包含.c）

c

运行

```
// 错误！直接包含 c 文件
#include "led.c"

void main(void)
{
    led_on();
    while(1);
}
```

### 编译过程发生了什么？

预处理会把 `led.c` 的全部代码复制进 main.c，此时 main.c 里已经有一份 `led_on()` 函数实体。

编译器编译时会分别编译：

1. 单独编译 `led.c` → 生成一份 `led_on` 函数
2. 编译 `main.c`（里面也复制了一份 `led_on`）→ 第二份 `led_on`
    
    链接阶段发现同一个函数有两份实体，直接报错：
    
    `multiple definition of 'led_on'` 多重定义

# 二、正确规范：只包含 .h，函数实体放 .c

## 1. 新建 led.h（只放宏、函数声明，无函数实现）

c

运行

```
#ifndef __LED_H
#define __LED_H

void led_on(void);  // 仅声明，没有大括号实现

#endif
```

## 2. led.c（放函数实现，包含自己的.h）

c

运行

```
#include "led.h"
#include <reg51.h>

void led_on(void)
{
    P0 = 0x00;
}
```

## 3. main.c（只包含 .h）

c

运行

```
#include "led.h"

void main(void)
{
    led_on();
    while(1);
}
```

### 编译流程（不会重复定义）

1. 编译 `led.c`：产生唯一一份 `led_on` 函数实体；
2. 编译 `main.c`：`#include "led.h"` 只导入函数声明，没有函数代码；
3. 链接时 main 调用的 `led_on` 去 led.c 里找，仅有一份，编译正常。

# 三、延伸坑：多个.c 互相包含.h 没问题，但不能包含.c

假设还有 `key.c`、`uart.c`

- main.c 包含 led.h、key.h、uart.h ✅ 合法
- led.c 包含 key.h ✅ 合法
- main.c #include "led.c" ❌ 报错多重定义
- key.c #include "led.c" ❌ 报错多重定义

# 四、一句话总结

`.c` 是实现文件，会被编译器单独编译生成函数实体；

`.h` 只是声明文件，只有函数原型、宏，不会生成函数代码；

一旦 `#include .c`，等于把完整函数代码复制到另一个文件，链接时出现重复函数。


## 2. 头文件重复包含（最常见场景）

当多个 `.c` 文件 `#include "LED.h"`，或者文件嵌套包含导致同一个 `.h` 被读取两次：

### 示例结构

- `main.c` 写了 `#include "LED.h"`
- `timer.c` 也写了 `#include "LED.h"`
- `main.c` 又 `#include "timer.c"`

预编译展开后，`LED.h` 的全部内容会被复制两份到代码里，产生两类问题：

1. **宏重复定义**：`#define __LED_H` 出现两次；
2. **函数 / 类型重定义**：`void LED_Init(void);`、结构体、枚举、typedef 重复声明，直接编译报错。

### 不加头文件保护宏的报错示例

plaintext

```
error: redefinition of '__LED_H'
note: previous definition of '__LED_H' was here
error: redefinition of 'LED_Init'
```

`#ifndef __LED_H` 这套保护，就是保证头文件内容**只会被展开一次**，杜绝重复。
